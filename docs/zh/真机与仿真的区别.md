# 真机操作与仿真的区别

## 1. 一句话

仿真里你启动 AMBF，系统免费得到 GT pose、GT depth、semantic mask 和无噪声坐标
关系；真机里你启动 dVRK 与相机，以上四样全部消失，必须用标定、视觉、同步和安全
流程补回来。

## 2. 同一 pipeline 的逐层替换

| 层 | 仿真 | 真机 | 真机新增失败模式 |
|---|---|---|---|
| RGB | AMBF camera topic | dVRK stereo camera topic | 曝光、反光、畸变、掉帧 |
| depth | AMBF GT 或 DA | DA/真实深度源 | 域偏移、尺度偏差、无 GT |
| needle mask | semantic object ID/proxy | 人工首帧或真实分割器 | 漏检、误检、遮挡 |
| needle pose | AMBF GT 或 FP | FP + physical gate | 180° 对称分支无 GT 告警 |
| PSM pose | AMBF measured state | dVRK kinematics + hand-eye | 机械柔性、关节/标定误差 |
| goal | 已知 frame chain | camera-frame needle + calibrated PSM | frame、单位、时间戳错 |
| action | AMBF command | dVRK servo/move API | 碰撞、速度、使能、急停 |
| success | AMBF state/termination | image/kinematics/人工确认 | 无真值、物理抓取不确定 |

`[测量]` 当前公开主线只验证到仿真 Reach 29/30；physical close/lift 和真机
hand-eye 均未验证。证据：
`docs/evidence/SurgicAI_SIM_S4_deployment_proxy_reach_20260811.md` 与
`docs/evidence/SurgicAI_D3a_handeye_preflight_20260806.md`。

## 3. 启动方式不同

### 仿真

顶层脚本负责：检查 domain → 启 AMBF → 等真实 State → 跑感知/控制 → 按 PID
关闭 AMBF。

```bash
python scripts/run_simulation.py --stage s4 --profile smoke --goal both --controller d2
```

### 真机

真机不运行 AMBF，也不使用 `/ambf/...` topics。典型顺序是：

1. 由授权操作者检查器械、工作空间、急停和旁站人员；
2. 启动 dVRK system，Power On/Home；
3. 启动左右相机并确认 `camera_info`、左右 rectified image；
4. 只读采集 hand-eye，离线求解并 overlay；
5. 采一段完全不发动作的 RGB/kinematics 数据，离线跑 DA/FP；
6. 人工确认首帧 needle mask/pose；
7. 只读显示 target 与 projected PSM；
8. 获得实验室批准后，分 translation/orientation/approach 三段低速授权；
9. Reach 连续稳定后才讨论 close/lift。

公开仓库没有“一键真机自动运动”命令，这是安全边界，不是漏文件。

## 4. hand-eye 是真机必需层

FoundationPose 输出 `T_camera_from_needle`；dVRK `measured_cp` 通常在 PSM base
坐标。两者不能直接相减。必须由 hand-eye 得到相机与机器人基座/末端之间的变换，
把 needle 和 PSM 变到同一坐标系。

只读 discovery：

```bash
source /opt/ros/<现场发行版>/setup.bash
source /path/to/dvrk_ws/install/setup.bash
bash src/handeye/discover_topics.sh "$HOME/handeye_discovery"
```

随后复制 `src/handeye/config/example_session.yaml`，填写现场确认过的：

- left/right image 与 `camera_info` topic；
- `/PSM1/measured_cp`、`/PSM2/measured_cp` 的消息类型和 frame；
- 图像分辨率、K、distortion；
- marker dictionary、边长、marker→tool 的刚性安装关系；
- 最大时间同步误差。

`[测量]` D3a synthetic noisy held-out p95 约 0.9–1.1 mm / 0.45–0.48°，但这不是
真机精度；报告 `docs/evidence/SurgicAI_D3a_handeye_preflight_20260806.md` 明确把
现场 topics/frame/K/marker/阈值列为未完成项。

### ECM 动了怎么办

如果 hand-eye 定义包含固定 ECM/camera 相对机器人基座的外参，那么 ECM 位置或安装
一旦改变，旧矩阵不再自动有效。必须：

- 重新采 hand-eye；或
- 同时可靠读取 ECM kinematics，并用已标定的 `ECM_tip↔camera` 固定变换在线更新。

在这两条都没验证前，第一次 demo 应固定 ECM；移动后继续用旧矩阵是 frame bug。

## 5. mask 的区别

### 仿真 semantic mask

renderer 直接告诉你“这些像素属于 Needle”。它是标签/特权输入。

### 真机 mask

真实图像只有颜色，没有 object ID。可选来源：

- 人在首帧画一个轮廓/框，再转成二值 mask；
- 分割模型自动输出；
- 检测器框 + SAM 类模型；
- background/颜色规则，仅能作为受控场景 baseline。

“人工首帧 mask”不是每个角度预存一张模板；是实验开始时人在当前真实画面上确认
针区域。FP 随后用 CAD + RGB + depth + mask 做首次 register。当前自动真机 mask
尚未验证，所以第一次真实 Reach 必须保留人工确认。

## 6. depth 的区别

仿真 GT depth 是每个像素准确的 renderer 距离。真机 DA 只从 RGB 预测，输入分布
变化会改变米制误差。

`[测量]` 相机 near-normal 时针像素从 502 增到 1619，但 needle depth MAE
p50/p95 从 0.769/1.696 mm 恶化到 26.516/33.489 mm；“看得更大”不等于 DA 更准。
证据：`docs/evidence/SurgicAI_SIM_S7_camera_generalization_20260813.md`。

所以真机先做离线验收：同一固定 ECM、真实 RGB、人工 mask；若没有真值 depth，至少
需要独立测距/已知平面/双目作为部分锚点。不能用仿真 DA 数字替代真机验收。

## 7. PSM 状态的区别

仿真可以同时读 PSM body GT。真机主线使用 dVRK kinematics + hand-eye，不使用
纯视觉 FP 跟 PSM。

`[测量]` pure visual PSM 多轮仍不 control-ready；去特权部署组甚至没有合格
candidate，见 `docs/KNOWN_LIMITATIONS.md` 与
`docs/evidence/SurgicAI_SIM_S6_uncertainty_fusion_20260813.md`。因此真机不会因为
“needle 和 PSM 都在画面里”就自动获得可靠相对 6D pose。

运动学仍可能有 5–10 mm 量级柔性/标定误差；正确处理不是盲信 FP top-1，也不是
盲信 kinematics，而是先 overlay 测真实误差，再决定是否用低增益视觉相对修正。

## 8. 控制与安全差异

| 仿真行为 | 真机要求 |
|---|---|
| runner 自动 reset | 人工摆针；没有 reset_invalid 分母 |
| 可以快速反复碰撞 | 先只读、后低速、分轴授权 |
| `kill PID` 后重开 | 必须使用 dVRK hold/disable/急停流程 |
| 3 mm/3° internal gate | 先由真实 hand-eye/柔性误差定可达合同 |
| termination 自动成功 | operator + kinematics + image 三方确认 |
| scripted attachment | 真机没有；必须物理 close/lift |

第一次真机演示建议把交付拆开：

- Level 1：Reach，连续到达、无碰撞、无方向反转；
- Level 2：close/lift/retention，作为独立物理抓取结果。

`[推断]` 这样拆分是因为仿真只对 Reach 有正面证据，而 scripted attachment 不能
迁移到真机；证据边界见
`docs/evidence/SurgicAI_SIM_S4_deployment_proxy_reach_20260811.md`。

## 9. 真机前最小清单

- [ ] topic/type/frame ID 实际回显，不只看旧 topic list；
- [ ] 左右相机 K/distortion/resolution 保存；
- [ ] ECM 固定，或已验证 ECM kinematics 更新外参；
- [ ] hand-eye train/held-out 分离，overlay 人眼可解释；
- [ ] PSM projected point/axis 与图像对齐；
- [ ] 真实 RGB 上 DA 离线运行，无 NaN/尺度灾难；
- [ ] 人工 needle mask 能稳定触发 FP register；
- [ ] 首帧物理门 + 人工确认；
- [ ] goal freshness/时间戳记录；
- [ ] 只读模式全链通过；
- [ ] translation、orientation、approach 分段低速批准；
- [ ] operator 明确 hold/disable/急停；
- [ ] Reach 与 close/lift 分开计数。

## 10. 不能直接从仿真带过去的数字

- SIM-S4 的 29/30；
- SIM-S3 的 40/40 gate acceptance；
- DA needle MAE 约 1 mm；
- hand-eye synthetic 约 1 mm；
- AMBF reset rejection；
- semantic-mask 条件下的 FP 成功率。

这些是仿真/合成条件下的证据，不是真机 KPI。真机必须在现场数据上重新测。
