# 仿真参数、错误码与排错树

## 1. 第一原则：按层排，不要一次改五个地方

```text
代码 -> Python -> ROS domain -> AMBF -> camera/depth -> DA -> mask
     -> FP/register gate -> goal bank -> PSM state -> controller -> artifact
```

上游层失败时，下游数字全部无效。例如 AMBF 已死，Python 仍循环，不是“policy
成功率低”，而是数据污染。历史共享 domain 事故记录在项目报告
`SurgicAI_Complete_Experiment_Report_20260721.md` 第 8 节。

## 2. 一键诊断

```bash
source /opt/ros/humble/setup.bash
source "$HOME/ambf_ros_ws/install/setup.bash"
cd "$HOME/suturing-policy-sim2real"
source .venv/bin/activate

python scripts/doctor.py --profile code
python scripts/doctor.py --profile reach --config configs/pipeline.env --check-domain-clean
python scripts/doctor.py --profile fp --config configs/pipeline.env --check-domain-clean
python scripts/doctor.py --profile full --config configs/pipeline.env --check-domain-clean
```

`code` 只查代码；`reach` 查冻结 bank/AMBF/RL；`fp` 查 GT depth→FP；`full`
再加 DA repository/checkpoint/SHA。

## 4. `D9-E60-S3` 怎么再切一层

| 最后存在的文件 | 卡在哪 | 看什么 |
|---|---|---|
| 只有 `domain_preflight_topics.txt` | AMBF 未 ready | `ambf_capture.log`；等真实 Needle State |
| 有 `reset_bank.log`，无完整 `reset_bank.json` | reset/camera ACK | `camera_capture.log` 的 frame/sequence |
| 有 capture，无 `da_result.json` | DA load/inference | `da.log` 的 SHA、CUDA、OOM、输入结构 |
| 有 DA，无 `fp_gate/result.json` | FP container/register | `foundationpose.log`、mesh/image mounts |
| 有 FP result，无 `MANIFEST.sha256` | 尾部中断 | 查结果是否 complete，再决定是否恢复 |

`[测量]` 旧链曾出现“15/20 实际走 GT passthrough 却看起来像 DA”的静默配对
错误；现 runner 按 episode+sequence 配对并把 source 写入结果。证据：
`docs/evidence/SurgicAI_SIM_S3_live_needle_initial_gate_20260811.md`。

## 5. `D9-E90-S4` 怎么再切一层

```bash
grep -R "artifact_complete\|reset_invalid\|Traceback\|ERROR" <run_root>/sim_s4
```

- `bank_build.log` 失败：S3 root 结构不完整，尤其是
  `fp_gate/candidates/*_DEPLOYMENT_PROXY.npz`；
- `ambf.log` 没真实 `/ambf/env/psm2/baselink/State`：world/plugin 没起来；
- `eval.log` 模型 load 失败：checkpoint/SB3 版本或 `PYTHONPATH`；
- exit 134 但 `artifact_complete=1` 且 episode 数正确：已知 ROS teardown；
- `reset_invalid`：场景生成门拒绝，不等于 policy action 失败；
- result 不足要求 episode 数：失败，不得拿部分结果冒充 formal。

## 6. 最重要的参数在哪改

所有主参数优先改 `configs/pipeline.env` 或命令行，不要改源码默认值。

| 参数 | 默认/正式值 | 含义 | 改动后还能否叫严格复现 |
|---|---:|---|---|
| `ROS_DOMAIN_ID` | 220 示例 | ROS 隔离域；Fast DDS 要求 1..232 | 可以，必须记录 |
| `SIM_S3_EPISODES` | 40 | 感知 reset 数 | 少于 40 只能叫 smoke |
| `SIM_S4_EPISODES` | 30 | 每个 Reach cell 数 | 少于 30 只能叫 smoke |
| `SIM_S3_X_MM/Y_MM` | 3/3 | 针 reset x/y 半宽 | 不可以 |
| `SIM_S3_YAW_DEG` | 15 | 针 yaw 半宽 | 不可以 |
| `SIM_S3_DEPTH_SOURCE` | `da` | `da` 或特权 `gt` | `gt` 是 A/B，不是部署结果 |
| `SIM_S4_CONTROLLER` | `goal-servo` | D2 或 policy | policy 是另一实验 |
| `SIM_S4_MODEL` | M3-100k | evaluator 初始化/policy | 换后必须报 SHA/合同 |

## 7. 容易误读的名词

### semantic mask

AMBF renderer 知道每个像素属于哪个物体，直接输出 needle object ID；这相当于
“答案标签”。它不会漏检、不会把血液/器械当针。真机 RGB 不含 object ID，必须由
人工首帧轮廓或分割模型生成 mask。`[测量]` SIM-S3 的 proxy mask 只是把 semantic
mask 做平移/腐蚀/膨胀，不是自动分割；证据：
`docs/evidence/SurgicAI_SIM_S3_live_needle_initial_gate_20260811.md`。

### GT depth / GT pose

- GT depth：AMBF renderer 给的米制深度，真实单 RGB 不会自带；
- GT pose：AMBF body state，真实系统也不会知道针真值；
- `--depth gt` 和 `--goal gt` 是诊断上限，不是部署配置。

### frozen goal

首帧 register 通过物理门后，把 goal 固定整条 episode。它要求 ECM 与针在控制期间
不动。它不是 live tracking；`[测量]` live 链达到过 3.302 Hz，但 pose age p95
仍 740 ms，见项目报告 `SurgicAI_P5d_gpu_timeslot_20260802.md`。

## 8. 不要做的“修复”

- 不要把 DA checkpoint SHA 门删掉；
- 不要把 FP >90°/物理门关掉让数字好看；
- 不要共享 ROS domain，不要 `pkill -f ambf_simulator`；
- 不要把 semantic mask 写成“自动 mask”；
- 不要把 S4 D2 29/30 写成 RL 29/30；
- 不要把 exit 0 当唯一成功，也不要把 exit 134 当唯一失败；
- 不要比较 single-goal 与历史 25-candidate termination 的 success rate。
